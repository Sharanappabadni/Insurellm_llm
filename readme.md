# Insurellm RAG Assistant

A lightweight, end‑to‑end RAG (Retrieval-Augmented Generation) application designed to answer questions based on Insurellm’s internal knowledge base.

It consists of two main components:

* **`ingest.py`**: ETL script that embeds markdown files into a Chroma vector database.
* **`answer.py`**: Streamlit frontend that queries the vector DB and uses Gemini to generate answers.

---

## 📂 Project Structure

The project assumes the `answer.py` and `ingest.py` scripts sit in the root alongside the vector database they share.

```bash
.
├── answer.py                # Streamlit app
├── ingest.py                # Database builder
├── knowledge-base/          # Source data (markdown files)
│   ├── employees/
│   │   ├── Emily Carter.md
│   │   └── ...
│   └── contracts/
│       └── Contract with GlobalRe Partners.md
├── requirements.txt
├── .env                     # API keys
└── vector_db/               # Generated by ingest.py (ChromaDB)

```

**Note:** All source documents must be placed inside `knowledge-base/` (supports subfolders).

## 🛠️ Setup & Installation

**1. Prerequisites**

* Python 3.10+
* A Google Gemini API Key

**2. Install Dependencies**
Create a virtual environment and install the required packages.

```bash
pip install -r requirements.txt

```

*Key dependencies:* `streamlit`, `chromadb`, `langchain`, `sentence-transformers`, `python-dotenv`.

**3. Environment Variables**
Create a `.env` file in the project root to store your credentials:

```bash
GOOGLE_API_KEY=your_gemini_api_key_here

```

> **Note:** `answer.py` uses this key to hit the Gemini API via the OpenAI-compatible endpoint.

## 🚀 Usage

### 1. Build the Vector Database

Before running the app, you need to parse the markdown files and generate embeddings. Run this from the project root:

```bash
python ingest.py

```

**What this does:**

* Scans `knowledge-base/` for `.md` files.
* Splits text into chunks using `RecursiveCharacterTextSplitter`.
* Embeds chunks using `all-MiniLM-L6-v2`.
* Saves the collection (`docs`) to `./vector_db`.

*If successful, you will see logs indicating the number of documents loaded and chunks created.*

### 2. Run the Assistant

Start the Streamlit interface:

```bash
streamlit run answer.py

```

Open your browser to `http://localhost:8501`.

**How to use:**

1. Check the sidebar—it should show the number of documents in the Vector DB (if it says 0, ingestion failed).
2. Type a question (e.g., *"What are the terms of the GlobalRe contract?"*).
3. The app will retrieve the top 5 relevant chunks and pass them to Gemini to generate an answer.

---

## 🧠 Architecture (High Level)

1. **Embedding:** We use HuggingFace's `all-MiniLM-L6-v2` for local, fast embeddings.
2. **Storage:** Data is stored in a persistent **Chroma** client located at `./vector_db`.
3. **Retrieval:** The app uses a similarity search to find the top  chunks relevant to the user query.
4. **Generation:**
* Retrieved text is formatted into a system prompt.
* The prompt enforces strict adherence to the context (i.e., if the info isn't there, say "I don't know").
* Gemini generates the final response.

## ⚠️ Troubleshooting / Gotchas

**"I don't know" answers**
If the model refuses to answer queries you know are in the docs:

* **Check Pathing:** Ensure `ingest.py` and `answer.py` are running from the *same* directory. If they point to different absolute paths for `vector_db`, the app won't see the data.
* **Collection Name:** Both scripts must target the Chroma collection named `docs`.

**Sidebar says "Vector DB docs: 0"**

* Ingestion likely failed or wrote to a different location.
* **Fix:** Delete the `vector_db/` folder and run `python ingest.py` again.

**Resetting the DB**
To completely wipe the database and start over:

```bash
rm -rf vector_db
python ingest.py

```
